# 2026-10-15 권한 및 저장 오류 수정

## 반영한 권한

| 역할 | 허용 범위 |
|---|---|
| 시스템 관리자 | 전체 과제·주간보고 CRUD, 개인 대시보드 본문/진척도/피드백 편집, 협력사/참여자 관리 |
| PMO | 소속 협력사 공지·참여자 CRUD, 소속 전체 개인 대시보드 조회, 본인 과제·보고서 CRUD |
| 참여자 | 소속 협력사 허브 현황 조회, 본인 과제·보고서 CRUD |

PMO에게 협력사 자체 삭제, 다른 참여자의 개인 과제 수정·삭제는 허용하지 않는다. 일정/PMO 명단과 협력사 주간 레포트 발행은 기존 관리자 전용 정책을 유지한다. 참여자는 과거 주간보고 조회만 가능하고, 관리자는 과거 보고서도 편집할 수 있다.

## 해결한 오류

- 같은 이메일의 여러 역할을 가진 참여자 목록을 수정하지 않았는데 변경으로 오인하던 diff 오류. 운영 과제 23개 중 20개에서 타인 수정분이 섞이던 원인을 제거했다.
- 참여자 목록을 이메일 키 하나로 합치지 않고 순서를 가진 전체 목록 CAS로 저장하여 여러 역할을 보존한다.
- 생성 요청은 기존 ID를 덮어쓰지 않는다. 서버와 DB가 모두 차단한다.
- 로그인 전 공개 응답은 협력사 id/name뿐이다. 대시보드 GET/PATCH 응답은 역할별 범위를 제한하고 참여자의 타인 보고서·참여자 상세 목록은 반환하지 않는다.
- PMO 로그인·세션 복구는 참여자 등록을 요구하거나 자동 생성하지 않는다. 기존 본인 참여자가 있으면 연결하며, 개인 대시보드 참여자 목록에는 본인 과제가 있는 PMO만 표시한다. 과제가 없는 기존 PMO 레코드는 삭제하지 않는다.
- 저장 실패 시 초안을 유지하고, 과제·참여자·공지는 재시도 때 같은 초안 ID를 사용한다. 성공한 경우에만 대화창을 닫는다.
- 주간보고 수정 시 저장 시각을 갱신한다. 구형 데이터의 빈 기본값과 숫자 형식도 비교 규칙을 맞췄다.
- DB 트랜잭션 안에서 역할·소속·현재 과제 소유권을 재검사한다. 짧은 저장 트랜잭션 동안 관련 테이블 쓰기를 직렬화하여 관리자 소유권 이동/참여자 이동과의 경쟁을 막는다.

## 검증

- Node 테스트 18개 통과. 그중 API→격리 PostgreSQL 통합 검사에 78개 권한 시나리오가 있고 불일치 0건이다.
- 운영 데이터 기반 원본 화면 클릭 처리/권한 검사 52개 시나리오: 수정 전 52건 거절 → 수정 후 52건 허용. 운영 저장 요청은 보내지 않았다.
- 실패한 과제·참여자·공지 등록 재시도, 중복 이메일 목록 보존, 기존 ID 덮어쓰기 차단, 저장시각 갱신, 과제/참여자 이동 후 이전 권한 차단을 회귀검사한다.
- 실제 Supabase에 연결한 수정 로컬 API에서 비로그인 401, 공개 목록 최소화, 참여자/PMO 소속 제한, 관리자 전체 조회를 확인했다.
- 검증 전후 운영 데이터 건수는 협력사 3, 참여자 26, 과제 23, 과제 주간보고 15, 협력사 레포트 3으로 유지됐다.
- 별도 코드 리뷰의 중요 지적 3건(참여자 재시도, 공지 재시도, 소유권 변경 경쟁)을 수정하고 실패→성공 회귀 테스트를 추가했다.

## 적용 상태와 재배포

운영 Supabase 프로젝트 winryyfctskibaajdyxv에는 위 마이그레이션의 함수를 SQL Editor에서 트랜잭션으로 적용했다. 새 함수 apply_authorized_dashboard_changes가 현재 역할·소속을 확인한 뒤 저장한다. 함수 본문 해시를 로컬 수정본과 비교했다. 운영 과제·보고서의 내용을 수정하거나 삭제하지 않았다.

로컬 D:\pjt-dashboard\ax-pjt-dashboard-main 수정본은 http://127.0.0.1:3080 에서 실제 Supabase에 연결해 실행 중이다. **기존 외부 배포 사이트의 애플리케이션 코드는 자동으로 바뀌지 않는다.** 이 수정본을 GitLab/호스팅에 반영해 재배포하고 브라우저를 새로고침해야 한다. GitLab 원격 커밋·푸시 또는 호스팅 재배포는 이번 작업에서 수행하지 않았다.

수정본 ZIP에는 .env, 키 값, node_modules, 로컬 DB 파일을 넣지 않았다. 배포 환경의 기존 Supabase 서버 환경변수를 유지한다.

~~~powershell
npm ci
npm test
npm start
~~~

새 DB에 설치할 때는 모든 마이그레이션을 순서대로 적용하거나 scripts/remote-schema.sql 전체를 사용한다. 운영 DB는 이번에 수동 적용했으므로 이후 db push에서 같은 마이그레이션이 다시 실행되어도 함수 교체만 이루어진다. 사용자 과제·보고서 데이터 초기화 명령은 실행하지 않는다.

기존 이름·이메일 로그인 수단 자체는 유지했다. 비밀번호/OTP/SSO를 통한 실제 신원 검증 도입은 이 수정의 범위에 포함하지 않았다. 서비스 운영 시 관리자 비밀번호와 SESSION_SECRET은 호스팅 환경변수로 관리한다.


참여자는 소속 협력사 허브의 전체 운영 요약·공지·PMO·운영 체크·과제별 진척현황을 조회할 수 있다. 허브용 요약 데이터는 개인 대시보드 저장 기준과 분리하며, 타인 과제의 보고서 본문·멤버·피드백 본문은 반환하지 않는다. 참여자의 상세보기는 본인 개인 대시보드로만 이동한다.


PDF 발행·재출력은 A4 실제 인쇄 폭(186mm)을 기준으로 웹 폰트 로딩 후 페이지를 계산한다. 표 행·문단·목록·제목 내부 페이지 나누기를 방지한다. 가상 과제 36건의 7쪽 PDF 전체를 렌더링해 확인했고, 표 행·문단 42개에서 경계 잘림이 0건이었다.
